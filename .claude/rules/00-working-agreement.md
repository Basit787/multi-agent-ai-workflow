# Working agreement — quote as `W3`

IDs match the shared working agreement; rules that only applied to other
repos are left out.

### W1 Do exactly what was asked
Only the named change, in the files it needs: no extra edits, files, docs,
tests, refactors or "while I'm here" fixes; a new file only when asked or when
the structure rules (`B2`, `F2`) put the code there. Anything else that looks
wrong: one sentence, leave it.

### W2 Endpoints are a contract
Path, method, guard, request schema, response body and status stay identical
unless the task is to change them. A changed endpoint updates
`apps/frontend/src/App.tsx` in the same change.

### W3 Minimal diff
No renames, reformatting, reordering or new dependencies unless asked.

### W4 Reuse what exists — never a parallel copy
Before writing any function, hook, type, schema, middleware or component, `grep` for one
that already does the job and call it as it is. Never a second version, wrapper
or "V2" beside it — auth and ownership checks above all.

### W5 Verify by running, not reading
Run the checks (`T7`); for backend behaviour, hit the endpoint (curl or
a throwaway Postgres container — never the user's data). Never call read-only
work "verified".

### W7 Forget build output
Never read or mention `dist/`, `node_modules/`, `.turbo/`, `pnpm-lock.yaml` or
`apps/backend/drizzle/meta/` (generated by `pnpm db:generate`).

### W8 Report only exceptions
A failed check (with output), something skipped (why), an assumption, a
blocking question.

### W9 No subagents or workflows unless asked
Only when the user asks for one or names it.

### W10 Feature docs only when the user mentions them
Write `claude/<feature>/` docs only when asked in that message.

### W11 Fewest tokens that still get it right
`grep` to locate, `sed -n 'A,Bp'` to read the region; whole files only when the
whole file matters. Never re-read what you just edited. Independent calls in
one message.

### W12 No preamble; close briefly
No plan or narration up front. Close with what changed and anything the user
must do by hand. A blocking issue gets one more sentence.

### W13 "Debug" means fix it in the same turn
A debug ask or a pasted error/log/screenshot: trace against the intended
behaviour and apply the fix now. Ask only if ambiguous or destructive.

### W16 "Remove / update / add this" — nothing else
Make it, fix broken imports and callers, run the checks, stop.

### W17 Plainest code, no invented abstractions
The file's existing shape; reuse what is in scope; no single-caller helpers,
key factories, wrapper hooks or options nobody asked for.
Why: self-invented helpers and wrappers were rejected and removed.

### W20 Build from the nearest existing implementation
Copy its structure, error shape and layout. Never invent an API field, enum
value, env var or helper; never leave a feature half-wired across frontend and
backend.

### W21 No debug logging unless asked
No added `console.log`; remove them when told.

### W25 Turn every ask into a precise prompt first — silently
Fix typos, restate internally as goal + target files + rules + done-check, fill
slots from the code, then act. Ask one question only if a slot cannot be filled.

### W26 Never delete code that wasn't named
Code that looks unused stays unless the user asked for a cleanup; on "remove
unwanted/dead code", remove only what `grep` proves has no caller and no side
effect, and list what went.

### W27 Git only on request
Commit, push or branch only when the user asks. Never push to `main`.

### W28 No comments in code
Do not write comments in client or server code: no `/** ... */` blocks and no
explanatory `//` lines. Only tool directives (`biome-ignore`, `@ts-expect-error`).

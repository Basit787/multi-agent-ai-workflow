GOAL
Today the client polls the API every 1.5–2 s while a workflow runs. Replace that with:
- Server: POST /api/workflows stores the run as "queued" and adds a BullMQ job (Redis). A worker
  with concurrency 1 runs the jobs one after another. Status goes queued → running → completed | failed.
- Events: GET /api/workflows/events is a Server-Sent Events stream of { workflowId, status, stepCount }
  for the signed-in user only.
- Client: no polling. One EventSource refreshes the queries and shows a toast when a run is
  generated or fails.
